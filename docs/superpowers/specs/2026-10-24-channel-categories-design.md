# Channel categories and discovery (phase 3 of the video overhaul) — Design

**Status:** Approved in chat (2026-10-24, from the user's request: "in the channels page we must be able to filter them by category to find channels that may interest us"). Builds on phase 2 (videos.categories/tags are captured and back-filled).

## Data
- `channels.categories TEXT` (JSON array, at most 3 names) = automatic categories: the categories that cover at least 15 % of the channel's enriched videos (`metadata_enriched_at IS NOT NULL`), most frequent first, ties alphabetical. `channels.categories_override TEXT NULL` (JSON array, at most 5 names, sanitised: trimmed, 1–40 chars, no control characters). Effective categories = override when set, otherwise automatic. Idempotent ALTERs in `server/utils/db.ts`; mirror in `tests/helpers/testDb.ts` (schema-parity must stay green).
- Recompute: `server/utils/channelCategories.ts` `recomputeChannelCategories(db, channelId?)`: after each download (when categories were saved), after each batch of the metadata backfill (every 25 videos and at the end), once at startup for channels whose `categories IS NULL` and that have enriched videos, and by a one-off migration. One grouped query for all channels (no per-video loop); a channel with no enriched videos keeps `categories = '[]'`.
- Home feed `byCategory` / `discoverChannels` and the subscriptions category filter keep working; where they derive categories on the fly, switch them to the effective channel categories where that is simpler (no behaviour change required).

## API
- `GET /api/channels` accepts `category=<name>` (exact, case-insensitive, matches effective categories), `q=<text>` (title contains, case-insensitive, ≤ 100 chars), `sort=title|videos|recent|watched` (default `title`; `recent` = newest upload; `watched` = viewer's watch time, logged-in only, else falls back to title), `following=1|0` (logged-in only: followed / not followed), `page`/`limit` (default 48, max 100); invalid values → 400; visibility rules unchanged (guests/users only see channels they may see, counts only over visible videos as today). Response adds `categories` (effective) to each channel and `total`.
- `GET /api/channels/categories` → `[{ name, count }]` over the channels the viewer can see (effective categories), sorted by count desc then name; cached per request only.
- `PUT /api/admin/channels/:id/categories` `{ categories: string[] | null }` (admin session; null clears the override); returns the effective categories.
- Tests: each parameter, 400s, visibility (a private channel's categories never appear for guests), counts, override vs automatic, recompute rules (15 % threshold, ties, max 3, no enriched videos), startup/migration, admin route auth (guest 401, member 403, token 403).

## UI
- `/channels` page rebuilt around discovery: a search box, a horizontally scrollable category chip bar ("All" + categories with counts; selection in the URL `?category=`), selects for sort and for "Following / Not following / All" (logged-in only), URL-synced (`?q=`, `?sort=`, `?following=`), a grid of channel cards (avatar, name, video count, category chips that filter when clicked, Subscribe/Following button with optimistic update and rollback, "N new" badge for followed channels), paging with "Show more", an empty state ("No channels match these filters" + Clear filters), a "Discover" strip at the top when logged in and no filter is active: up to 8 channels the user does not follow, ranked by overlap with the user's top watched categories then popularity, with a short reason ("Because you watch Gaming").
- Channel page header and the Tracking options drawer (admin): show the channel's category chips; the drawer gets a "Categories" editor (chips with remove, add from the known categories list or free text, "Reset to automatic") that calls the admin route.
- Subscriptions and Home reuse the same chip component. English copy, explicit 'en-US' locale, phone friendly, keyboard-operable chips (aria-pressed), loading skeletons.
- Tests: component tests for the filters/URL sync/empty state/subscribe optimistic rollback/admin editor; live check by the controller in the real browser.
