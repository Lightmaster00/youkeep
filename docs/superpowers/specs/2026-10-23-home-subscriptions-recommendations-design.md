# New Home, Subscriptions and Recommendations (phase 2 of the video overhaul) — Design

**Status:** Approved in chat (2026-10-23). Phase 1 (quick fixes) is merged. Phases 3 (channel categories), 4 (languages), 5 (logo) follow. Delivered in two parts: **2A data + recommendation engine + feed API**, **2B Home and Subscriptions UI**.

## Data (part 2A)
- `videos`: `categories TEXT` (JSON array of YouTube category names, e.g. ["Gaming"]), `tags TEXT` (JSON array, at most 20 lower-cased tags), `metadata_enriched_at INTEGER`. Idempotent ALTERs in `server/utils/db.ts`; mirror in `tests/helpers/testDb.ts` (schema-parity test must stay green). Index on `videos(metadata_enriched_at)` is not needed; index `idx_videos_channel_upload ON videos(channel_id, upload_date)` if missing.
- `user_history`: `position_seconds INTEGER NOT NULL DEFAULT 0`, `duration_seconds INTEGER`, `position_updated_at INTEGER`.
- Capture: `server/utils/videoInfo.ts` (`extractInfoFields`) also returns `categories` and `tags` (arrays of strings, sanitised: trimmed, ≤ 40 chars each, max 3 categories and 20 tags); the downloader stores them with the other info fields after a download.
- Backfill for existing videos: `server/utils/metadataBackfill.ts`, a resumable background job that fills categories/tags for completed videos with `metadata_enriched_at IS NULL`: one video at a time, `yt-dlp --skip-download --dump-json --no-playlist -- <watch URL>` (id validated, 60 s timeout, process-group safe via the existing helpers), at most one request every 4 s, never while shutting down, backs off on errors (a video that fails 3 times is marked enriched with empty arrays so it never blocks the queue), pauses while the downloader is blocked. Setting `metadata_backfill_enabled` (default '1'); started 120 s after boot when there is work. Admin tool in Settings → System → Tools & logs: "Video categories" panel (counts: total / enriched / pending, toggle, "Run now", status) with routes `GET /api/admin/system/metadata-backfill/status`, `POST …/start`, `POST …/settings {enabled}` (session-admin only, same pattern as the album-match panel/routes).
- Server-side resume position: `POST /api/videos/track` accepts optional `positionSeconds` (0..86400) and `durationSeconds`; stores them (clamped; `position_updated_at = now`). `GET /api/videos/continue?limit=` (logged in) → in-progress long videos (position ≥ 10 s and < 95 % of duration, newest `position_updated_at` first, visible + non-hidden) with `positionSeconds`, `durationSeconds`, `progress` (0..1). The watch page posts the position together with the existing watch-time ticks and resumes from the server position when no `?t=` is given (localStorage stays a fallback for guests).

## Recommendation engine v2 (part 2A)
`server/utils/recommend.ts` keeps its public API (`getRecommendedVideos(db, viewer, { type, limit })`) and gains `{ seed?, exclude?, reasonLabels? }`; the implementation moves to a pure, tested scoring module `server/utils/recommendScore.ts`.
- User profile (logged in): per channel affinity = Σ over history of `min(watch/duration, 1)` (fallback: watch seconds / 600 capped at 1 when duration unknown) × recency weight `0.5^(daysAgo/30)`; per category and per tag affinity derived from those watched videos (normalised 0..1); subscribed channels (`user_subscriptions`); hidden videos and already-completed videos excluded.
- Candidate pool: the 600 newest + 200 most viewed visible completed videos of the requested `type` (long videos by default), de-duplicated.
- Score = `0.35·channelAffinity + 0.2·categoryAffinity + 0.1·tagOverlap + 0.15·subscriptionBoost + 0.1·freshness + 0.1·popularity`, where freshness = `0.5^(ageDays/14)`, popularity = `log10(1+views)/log10(1+maxViews)` (local viewers add a small bump). Already-started videos (position ≥ 10 s, < 95 %) are excluded here (they belong to "Continue watching"). Per page: at most 2 videos per channel (greedy re-ranking), and 10 % of slots are exploration picks (unseen channel/category with a decent popularity). Deterministic: jitter derived from a hash of `(seed, video id)` (±8 %), `seed` defaults to the current hour; no `Math.random`.
- Cold start (no history/subscriptions): popularity 0.5 + freshness 0.3 + category diversity (round-robin over categories) 0.2.
- Guests: same as cold start over public content.
- Each result carries `reason`: `{ kind: 'subscription'|'because-watched'|'category'|'popular'|'new', label: string, ref?: {videoId?, channelId?, category?} }` with an English label ("From a channel you follow", "Because you watched <title>", "Popular in <category>", "Popular on your server", "New").
- Tests (pure module with synthetic fixtures): subscribed channel ranks above an equal non-subscribed one; recency decay of affinity; category affinity lifts same-category videos; watched/completed/hidden excluded; started videos excluded; at most 2 per channel; exploration slot present and never from hidden/ineligible; determinism for the same seed and a different order for a different seed; cold-start variety; reason labels; visibility respected (guest never gets private); performance budget (20k videos, 50k history rows < 500 ms).

## Feed API (part 2A)
`GET /api/home/feed` is extended (same endpoint, same response envelope; read the current shape first and keep it backward compatible for the existing client until 2B lands): new sections, each omitted when empty, long videos only unless stated:
`continue` (continue watching), `subscriptions` (latest per followed channel, ≤ 2 per channel, newest first, flagged `isNew` when the user has no history row), `forYou` (recommendations with reasons), `popular`, `becauseYouWatched` (seeded by the most recently watched video: same channel/category/tags, excluding watched), `byCategory` (up to 3 rows, one per top category of the user's profile — or the most common categories for guests — each `{ category, videos }`), `shorts` (Shorts only, vertical shelf, newest/popular mix), `playlists` (the user's 6 most recently updated personal playlists with cover + count), `discoverChannels` (library channels the user follows not and has watched little, ranked by popularity within the user's top categories, with avatar, title, video count, categories), plus `recentMusic`/`newEpisodes` unchanged. Row size honours `rowSize`. `shared/displayPrefs.ts`: `HOME_SECTION_IDS` becomes `['continue','subscriptions','forYou','popular','becauseYouWatched','byCategory','shorts','playlists','discoverChannels','recentMusic','newEpisodes']`; the old id `suggested` is accepted and mapped to `forYou`; guests may see `popular`, `byCategory`, `shorts`, `recentMusic`, `newEpisodes`. New default list for everyone: `['continue','subscriptions','forYou','popular','becauseYouWatched','byCategory','shorts','playlists','discoverChannels']`. A stored list equal to an old default (`['popular','suggested','subscriptions']`, optionally with `recent`) counts as "never customised" and is replaced by the new default; any other stored list keeps the user's choice (with `suggested`→`forYou`). Admin default and user override keep working; `isHomeFullyHidden` updated.
- Subscriptions data routes (used by part 2B): `GET /api/subscriptions/feed?channelId&category&sort=new|popular|oldest&type=video|short&page&limit` (logged in) → `{ videos, total, groups? }` where each video has `isNew` and `watchedPercent`; `GET /api/subscriptions/channels` → followed channels with `newCount` (videos uploaded after the user's last visit/unwatched in the last 14 days), `lastUploadAt`, `videoCount`, `categories`; `POST /api/subscriptions/seen` `{ videoId }` marks as seen (history row with 0 watch time is NOT created — use a new tiny table `user_seen_videos(user_id, video_id, seen_at)` idempotent) and `POST /api/subscriptions/mark-all-seen`. `isNew` = no history row and no seen row.

## Home page (part 2B)
`app/pages/index.vue` renders the sections in the user's order: hero (best `forYou` long video, falling back to newest subscription video), then each section as a row component: video rows use `VideoCard` (reason label under the card for `forYou`/`becauseYouWatched` rows; "Continue watching" cards show a progress bar and "Resume"), `shorts` = vertical shelf of Short cards with horizontal scroll and a "See all Shorts" link to /shorts, `playlists` = playlist cards, `discoverChannels` = channel cards with a Subscribe button and category chips. Each row has a title, optional "See all" link where a destination exists (subscriptions, channels, shorts, playlists, search by category), horizontal scroll with keyboard-accessible arrows on desktop, and skeleton loading placeholders per row. Display preferences form lists the new rows with the same up/down/toggle UI. Empty library and fully hidden states still work. Phone width friendly; English copy.

## Subscriptions page (part 2B)
`app/pages/subscriptions.vue` rebuilt: header with a horizontally scrollable chip bar (All + each followed channel with avatar and a dot when it has new videos), tabs **Latest** | **Channels**; Latest = chronological grid grouped by day (Today / Yesterday / This week / Earlier) with a "New" dot on unseen videos, a "Mark all as seen" button, filter by category (select), sort (Newest/Most viewed/Oldest), a separate "Shorts" section below (never interleaved), "Show more" paging; Channels = grid of followed channels (avatar, name, new count, last upload relative time, categories chips, unsubscribe with confirm); empty state suggests channels (reuse `discoverChannels` data). Seen tracking: a video marked seen when opened or when ≥ 50 % visible for 2 s (IntersectionObserver, debounced batch to `/api/subscriptions/seen`, never for guests). Component tests with stubbed $fetch for every state.

## Testing summary
Server: schema/migration, extractInfoFields, backfill job (injected runner: ordering, throttle with fake timers, failure marking, shutdown, no real yt-dlp), track/continue routes, scoring module, feed sections (visibility per role, order, empties, prefs migration), subscriptions routes. Client: home sections, rows, prefs form, subscriptions page states. Live check by the controller in the real browser with seeded data (4 channels, categories, history, subscriptions, shorts, playlists).
